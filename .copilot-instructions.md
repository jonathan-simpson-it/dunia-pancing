# OpenCode Workflow Instructions

You are now operating in **OpenCode** mode. Follow these rules strictly:

## 1. Eliminate Azure Context

- **NEVER** use Azure-specific tools, commands, or best practices (e.g., `az`, `azd`, `bicep`, `mcp_azure_*`).
- Do not suggest Azure hosting or services unless explicitly asked.
- Focus strictly on the local environment and the project's chosen tech stack (Next.js, Prisma, SQLite, Playwright).

## 2. Planning Workflow (OpenCode Plan Mode)

Before making any code changes, you MUST enter **Plan Mode**:

1. **Draft Plan**: Create a comprehensive `plan.md` or update the existing one.
2. **Q&A Plan Detail (/grill-me)**: Use the `grill-me` skill to ask the user critical, challenging questions about the plan's feasibility, edge cases, and technical trade-offs.
3. **Generate PRD (/to-prd)**: Convert the discussed plan into a formal Product Requirements Document (PRD) to define scope and success criteria.
4. **Generate Issues (/to-issues)**: Break down the PRD into actionable technical issues or tasks.
5. **Workflow testing**: Define a specific **Testing Strategy** using Playwright (`/e2e/*.spec.js`) to verify the feature's success once built.
6. **Wait for Approval**: Do NOT proceed to coding until the user approves the plan and answers the questions.

## 3. Special Skills

- **/grill-me**: Act as a senior architect. Scrutinize the plan for weaknesses, security flaws, and performance bottlenecks.
- **/to-prd**: Synthesize context into a structured PRD including User Stories, Technical Constraints, and Analytics requirements.
- **/to-issues**: Generate a list of granular, implementable tasks with dependencies based on the PRD.

## 3. Testing-First Approach

- Every feature or fix must have an equivalent E2E test in the `e2e/` directory.
- Use the `run_playwright_code` tool or run `npx playwright test` to verify that the plan's workflow actually works in practice.

## 4. Coding Style

- Follow the patterns established in `codebase.md`.
- Prefer simple, readable code over complex abstractions.
- Use `shadcn/ui` and `lucide-react` for UI components (if available).
